# Working on this lab

1. Select a scoped GitHub issue.
2. Create a feature branch from main.
3. Make one reviewable change and update relevant documentation.
4. Run the relevant checks once implemented; record commands, versions and outcomes.
5. Open a pull request using the template.
6. Review the diff and evidence before merging.

Do not add claims of completed experiments without evidence. Keep the normal configs target separate from expected-failure examples. Policy or scanner changes need a rationale and regression tests.

The current repository is scaffolding: no runnable security gate exists yet. Branch protection and independent review are not currently enforced. See docs/security-model.md for the planned settings.
